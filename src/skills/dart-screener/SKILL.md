# DART 재무 레드플래그 스크리너

회계사·감사인이 특정 기업의 재무제표에서 금감원 감리 지적사례 패턴을 사전 점검할 때 사용한다.

## 사전 조건

- 환경변수 `DART_API_KEY` 또는 작업 디렉토리(상위 포함)의 `.env`에 `DART_API_KEY=...`가 필요하다.
- 키가 없으면 실행을 멈추고 안내한다: "https://opendart.fss.or.kr 에서 무료 API 키를 발급받아
  .env 파일에 DART_API_KEY=키 형태로 저장해 주세요." **사용자에게 키를 채팅에 직접 입력하라고
  요구하지 않는다.**
- API 키를 어떤 출력·리포트에도 포함하지 않는다.

## 실행 절차

모든 스크립트는 이 스킬의 `scripts/dart_client.py`를 사용한다 (표준 라이브러리만 사용, 설치 불필요).

### 1단계 — 기업 식별

```bash
python3 {스킬경로}/scripts/dart_client.py find "기업명"
```

- 결과가 여러 개면 상장사(stock_code 있음)를 우선하되, 동명 기업이 애매하면 사용자에게 확인한다.

### 2단계 — 지표 수집

```bash
python3 {스킬경로}/scripts/dart_client.py metrics <corp_code> --years 3
```

- 기본은 연결재무제표(CFS) 3개년. 오류가 나면 `--fs OFS`(별도)로 재시도한다.
- 사용자가 기간을 지정하면 `--years N`, 과거 특정 시점 점검이면 `--end YYYY`를 쓴다.
- 원시 계정값 검증이 필요하면 `collect` 커맨드로 확인한다.
- 참고: DART 전체 재무제표 API는 2015 사업연도 이후 상장사만 지원한다. 실패 시 이 한계를 안내한다.

### 3단계 — 룰 판정

`references/red-flag-rules.md`를 읽고 R1~R10을 **하나씩 전부** 판정한다.

- 각 룰의 임계치·판정 기준·매핑 지적사례를 그대로 따른다.
- 등급: 🔴 HIGH / 🟡 WATCH / ⚪ CLEAR / ➖ N/A
- 계산 불가(N/A) 룰도 건너뛰지 말고 사유와 함께 보고한다.

### 4단계 — 리포트 작성

아래 구조의 마크다운 리포트를 생성한다 (대상 독자: 회계사 — 전문용어 사용 가능):

```markdown
# [기업명] 재무 레드플래그 점검 리포트
- 대상: [기업명] (corp_code, 종목코드) / [연도범위] [연결|별도]
- 생성: [날짜] / 데이터 출처: DART Open API (opendart.fss.or.kr)

## 요약
| 룰 | 항목 | 판정 | 핵심 근거 |
(R1~R10 전체 — 판정 등급 순 정렬)

## 상세 분석 (🔴·🟡 룰만)
### [룰 번호·이름]
- 근거 수치: 연도별 값 vs 임계치
- 매핑 지적사례: [금감원 사례 유형 + 출처 인용]
- 권고: 확인해야 할 감사절차·주석 항목

## 주석 확인 체크리스트 (R10)
- 우발부채(투자자 약정·풋옵션), 특수관계자 담보·보증 등

## 한계 고지
(red-flag-rules.md의 "리포트 필수 원칙" 4항 반영)
```

## 절대 규칙

- **단정 금지**: "분식회계"로 단정하지 않는다. "지적사례 유형과 유사한 패턴, 추가 검토 필요"로 서술한다.
- 모든 플래그에 근거 수치를 병기한다. 수치 없는 판정은 출력하지 않는다.
- 리포트를 파일로 저장해달라는 요청이 없어도 `red-flag-report-[기업명]-[날짜].md`로 저장을 제안한다.
