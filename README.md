# DART Red-Flag Screener — 금감원 감리 지적사례 기반 재무제표 스크리닝 Codex 플러그인

> AX 해커톤 예선 제출물 · 대상 기업: **삼일PwC**

## 어떤 문제를 푸는가

삼일PwC 같은 회계법인의 감사인은 감사 착수 전·중에 대상 기업 재무제표의 **이상 신호(레드플래그)**
를 식별해야 한다. 금융감독원은 이를 돕기 위해 2011년부터 회계심사·감리 지적사례를 누적 202건
공개해 왔고, 2024년부터는 공개 주기를 연 2회로 단축했다 — 그러나 이 사례들은 **PDF·보도자료
형태의 비정형 텍스트**라서, 개별 기업 재무제표에 체계적으로 적용하려면 감사인이 수작업으로
계정을 뽑아 비율을 계산해야 한다.

- 감리 지적은 실제로 빈번하다: 삼일 포함 10개 회계법인 품질관리 감리에서 평균 8건 지적
  ([이투데이 2026-06-01](https://www.etoday.co.kr/news/view/2589566))
- 신외감법 이후 감사보수는 84.1% 올랐지만 품질 개선은 입증되지 못했다
  ([아시아경제 2023-04-14](https://view.asiae.co.kr/article/2023041210055463302))
- XBRL 공시 확대에도 이를 활용할 실무 도구는 부재하다
  ([파이낸셜뉴스 2024-09](https://www.fnnews.com/news/202409252022309788))

이 플러그인은 금감원 지적사례를 **10개 정량·정성 룰로 코드화**하고, DART Open API로 재무제표를
자동 수집해 룰을 적용한 뒤, 지적사례 유형을 인용한 점검 리포트를 생성한다.

## 구성

```
src/                                  # 플러그인 루트
├── .codex-plugin/plugin.json         # 매니페스트
└── skills/
    ├── dart-screener/                # 메인: 단일 기업 레드플래그 정밀 점검
    │   ├── SKILL.md                  # 스킬 지시문 (수집→룰 판정→리포트)
    │   ├── scripts/dart_client.py    # DART API 클라이언트 (표준 라이브러리만, 의존성 0)
    │   └── references/red-flag-rules.md  # 룰 10개 ↔ 지적사례 ↔ 출처 매핑
    └── peer-compare/                 # 보조: 동종업계 비교로 기준선 보완
        └── SKILL.md                  # (dart-screener의 스크립트 재사용)
```

설계 원칙: **숫자는 스크립트가(결정적), 해석은 AI가(지시문 기반)**.
`dart_client.py`는 기업 검색·재무제표 수집·지표 계산만 수행하고, 룰 판정과 리포트 서술은
Codex가 `red-flag-rules.md`의 임계치·매핑 기준을 따라 수행한다.

## 룰셋 요약 (금감원 2025 하반기 지적사례 10건 매핑)

| 룰 | 점검 항목 | 매핑 지적사례 |
|---|---|---|
| R1 | 매출채권-매출 괴리 | 매출 과대계상 (매출·매출원가 3건) |
| R2 | 매출총이익률 급변 | 총액/순액 인식 오류 (개인방송 중개 사례) |
| R3 | 영업이익-영업현금흐름 괴리 | 손실 인식 지연 |
| R4 | 재고자산 급증 | 매출원가 과소계상 |
| R5 | 충당부채 미인식·급감 | 공사손실충당부채 과소계상 (ERP 조작 사례) |
| R6 | 지분법투자 손상 미인식 | 종속·관계기업투자주식 2건 |
| R7 | 무형자산·영업권 이상 | 사업결합 무형자산 과소계상 |
| R8 | 전환사채 부채·자본 배분 | 전환사채 배분 오류 |
| R9 | 대손충당금 설정률 이상 | 기타 자산·부채 |
| R10 | 주석 공시 체크리스트 (정성) | 우발부채·특수관계자 담보 미공시 2건 |

## 검증 — 실제 감리 사례 백테스트

룰셋이 실제 사고를 잡아내는지 **과거 감리 대상 기업의 당시 공시 데이터**로 검증했다.

**양성 검증 — 셀트리온헬스케어 (2018년 금감원 감리 착수, 매출채권 회전 이슈)**

| 연도 | 매출채권/매출 | 영업이익 | 영업현금흐름 |
|---|---|---|---|
| 2017 | 45.5% | +1,648억 | **-1,943억** |
| 2018 | **58.3%** | -426억 | **-1,842억** |
| 2019 | 35.4% | +828억 | **-1,638억** |
| 2020 | 25.2% | +3,621억 | **-226억** |

→ R1(매출채권/매출 40% 초과) 🔴, R3(4년 연속 이익-현금흐름 괴리) 🔴 — 당시 감리 착수의
실제 핵심 지표를 정확히 포착.

**음성 대조 — 삼성전자 (2023~2025)**: 매출채권/매출 14~15%, CFO가 영업이익의 2배로
핵심 룰(R1~R4·R6~R8) 전부 CLEAR — 과탐지 없음. R5(충당부채 -64.7% 급감)만 🟡 WATCH로
표시하고 "주석에서 환입·사용 사유 확인 필요"를 권고 — 건전 기업에서도 확인이 필요한 신호는
숨기지 않고 근거와 함께 보고하는 설계다.

## 한계

- DART 전체 재무제표 API는 2015 사업연도 이후 상장사만 지원한다.
- 표준계정 매핑 기반이라 기업별 계정 분류 차이로 일부 룰이 N/A가 될 수 있다 (리포트에 명시).
- 결과는 "분식 판정"이 아니라 **추가 검토가 필요한 신호**다. 최종 판단은 감사인의
  감사보고서·주석 검토가 필요하다.
